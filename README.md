# СТМ 2.0 — облачна основа (v0.1, НЕ продукционна система)

**Важно:** Това е основа за разработка и **не е сертифицирана система за реални здравни данни**. В този пакет няма реални ЕГН, медицински файлове, пароли, токени или съдържание на старите EMS-STM архиви.

## Технологии

- Next.js 16, React 19, TypeScript, Server Actions.
- Supabase Auth (сесии през `@supabase/ssr`, без публична регистрация).
- PostgreSQL с RLS и разделяне по организация/роля, моделирано в `supabase/migrations`.
- Vercel за прегледи и деплой, GitHub за версиониране и CI.

## Функционални части към v0.1

- Истинска форма за вход в Supabase **само след конфигурация**; без фалшиви потребители.
- Профил без членство няма достъп до регистрите.
- Табло с реални броячи от разрешените записи; регистри по модули.
- Добавяне на фирми (входна и RLS проверка), търсене, странициране.
- Контролирани CSV експорт на фирми и основни служебни данни; без здравни диагнози/ЕГН.
- Статичен публичен `/preview`, съдържащ **само измислени данни**.
- SQL схема за организации, роли, ограничен достъп по фирма, персонал, записи за прегледи, болнични (само базов статус), метаданни на документи, миграционни партиди и мета-одит.

## Все още не е реализирано

- Създаване и управление на акаунти/покани от интерфейса; управление на много организации.
- Пълният фирмен регистър от стария AAMDB, присвояване на служители и болнични към пациенти.
- Реални прикачени файлове в Supabase Storage и частните политики за тях.
- Пълна медицинска история, диагнози, медицински регистри, шаблони и отчети.
- Потребителско управление/редакция на всички видове записи.
- Изпълнени интеграционни тестове на реален Supabase проект; възстановяване от backup в упражнение.
- Правен преглед (GDPR, чл. 9/28/32/35; български правила за СТМ), DPA, DPIA и политики за запазване.

## Стартиране на разработката

1. Създайте **нов, отделен Supabase проект** в подходящ EU регион; не използвайте съществуваща чужда база.
2. Прегледайте `docs/SECURITY.md` и SQL миграцията. Приложете я първо в тестов проект.
3. Добавете проектните env стойности само във Vercel Environment Variables и локален `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
4. `npm install`, `npm run dev`, `http://localhost:3000`.
5. За първия потребител: поканете/създайте потребител чрез Supabase Auth Dashboard, след което собственикът на проекта създава `tenants` и `tenant_members` чрез Dashboard SQL Editor. Пример без реални данни:

```sql
insert into public.tenants(name) values ('Тестова СТМ') returning id;
-- Използвайте върнатото tenant id и реалния auth.users.id от Dashboard.
insert into public.tenant_members(tenant_id,user_id,role)
values ('YOUR_TENANT_UUID','YOUR_AUTH_USER_UUID','admin');
```

Няма отворена форма за регистрация. Не използвайте `service_role` key в `NEXT_PUBLIC_*`, в браузър или в GitHub.
