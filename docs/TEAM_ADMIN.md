# Управление на потребителите (СТМ 2.0 v0.3 — тестова версия)

Потребителите се създават **само ръчно** от собственика в Supabase → Authentication → Users → Add user → Create new user.

След създаването администраторът отваря **/app/team** и добавя съществуващия имейл и роля. При роля „работодател“ задава минимум една фирма.

Приложението **не изпраща имейли и не създава Supabase акаунти**. Не се използва service role ключ от Team Actions. Не споделяйте пароли.

Има 5 роли: admin, specialist, doctor, employer, auditor. Supabase RLS ограничава достъпа до конкретните фирми. Лекарските записи остават отделени от работодателите.

Защитата на базата не позволява:
- анонимен достъп до списъка с акаунти;
- администратор да отнеме собствените си admin права;
- деактивиране на последния активен администратор;
- активен работодател без назначена фирма;
- назначаване на фирма от друга CTM организация.

Историята на промените на ролите се записва в audit_events (метаданни).

## Ограничения

- SQL RPC за администриране се извикват от удостоверен потребител и имат проверки за активен admin в целевия tenant. Supabase Security Advisor отбелязва exposed SECURITY DEFINER функции — необходимо е отделно hardening и проникващи тестове преди реални здравни данни.
- Не е потвърдено, че всички роли са тествани със собствени акаунти.
- UI зарежда максимум 100 фирми и 1000 разрешения. Пагинацията е предстояща.
- Този проект все още НЕ е предназначен за реални ЕГН или медицински досиета.
